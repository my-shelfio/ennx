# ennx 開発着手

イシュー番号: $ARGUMENTS（未指定の場合はオープンなイシューを一覧し、対象を確認してから進める）

事前に CLAUDE.md と .claude/rules/ を読むこと。各ステップは**進行条件を満たすまで次に進まない**。

## 手順

### 1. イシューの把握とベースブランチの決定

- `gh issue view <番号>` で本文を読み、受入条件と「依存・ブロック」欄（`依存: ` / `ブロック: ` の行。Issue Forms 化されたテンプレートではセクション見出しの下に記載される）を確認する
- **依存イシューが未マージの場合**: 依存先ブランチをベースにする（git-workflow.md）。依存先ブランチが存在しない場合は依存イシューを先に対応するか、ユーザーに確認する。
- 進行条件: 受入条件を箇条書きで再掲し、ベースブランチを宣言した

### 2. ブランチ作成

- ベースブランチを最新化し、`<prefix>/<イシュー番号>` で分岐（prefix はイシューのラベルから
  git-workflow.md の表で判定）
- 進行条件: `git status -sb` でブランチ名とベースを確認した

### 3. 実装

- アルゴリズムの移植・追加を含む場合は **ennx-algorithm-port スキルの手順に切り替える**
- バグ修正の場合は **ennx-bugfix スキルの手順に切り替える**
- testing.md の必須テスト（変更種別に応じたもの）を実装と同時に書く
- 進行条件: 受入条件の各項目に対応する実装・テストがある

### 4. 品質ゲート

- CLAUDE.md「品質ゲート」の4コマンドを順に実行し、全通過させる
- 指摘が出た場合: 自ブランチ由来なら修正、先行ブランチ由来なら先行ブランチで修正して再マージ
- 進行条件: 4コマンドすべての通過を出力で確認した

### 5. Draft PR 作成とセルフレビュー

- コミット・プッシュし、PR テンプレート（.github/pull_request_template.md）の全セクションを
  埋めて **Draft PR** を作成する（ベースはステップ1で決めたブランチ。スタックPR の場合は
  マージ順を「その他」に明記）
- ennx-review スキルの手順でセルフレビューを行う（reviewer の指摘は PR のレビューコメント
  として投稿し、履歴を残す）
- 「要修正」の指摘があればステップ3に戻り、修正を追加コミットとしてプッシュして再レビューする
- 総合判定が「Ready for review 可」になったら PR 本文の「レビュー観点」「懸念点」を更新し、
  `gh pr ready <番号>` で Draft を解除する
- 進行条件: PR が Ready for review である

## 完了チェックリスト（全項目 yes で完了）

- [ ] ブランチ名が `<prefix>/<イシュー番号>` である
- [ ] 受入条件の全項目に対応する実装・テストがある
- [ ] 品質ゲート4コマンドが全通過している
- [ ] reviewer エージェントの判定が「Ready for review 可」で、指摘が PR のレビューコメントとして残っている
- [ ] PR 本文がテンプレート準拠で、スタックPR ならマージ順が明記されている
- [ ] Draft が解除され、PR が Ready for review になっている
