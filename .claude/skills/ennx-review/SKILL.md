# ennx セルフレビュー

対象: $ARGUMENTS（省略時は現在の作業ブランチの PR、PR 番号指定時はその PR）

レビューの指摘・対応の履歴は PR のレビューコメントとして残す
（git-workflow.md「PR・レビュールール」）。チャット内・ローカルのみで完結させない。

## 手順

### 1. レビュー対象 PR の特定

- PR 番号指定時は `gh pr view <番号>`、省略時は `gh pr view`（現在ブランチの PR）で
  head / base を確認する
- **PR が存在しない場合は、先にコミット・プッシュして Draft PR を作成する**
  （PR テンプレート準拠。ennx-develop-work 手順5）
- 進行条件: PR 番号と差分の範囲（base...head）を宣言した

### 2. reviewer エージェントへの委譲

- ennx-reviewer エージェントを起動し、対象 PR（番号・差分範囲）を伝えてレビューを依頼する
- **実装した本人（メインコンテキスト）は判定に関与しない**。エージェントの指摘に
  反論がある場合も、まず指摘の根拠（ルール引用・実行結果）を確認する
- 進行条件: 指摘一覧・レビュー観点・懸念点・総合判定を受け取った

### 3. 指摘の PR への投稿

- エージェントの指摘一覧・総合判定を**加工せずそのまま** PR のレビューコメントとして
  投稿する（`gh pr review <番号> --comment --body ...`）
- 再レビューのラウンドごとに投稿する（履歴をすべて残す）
- 進行条件: 今回ラウンドのレビューコメントが PR 上に存在する

### 4. 指摘への対応

- high の指摘: 修正を追加コミットとしてプッシュし、ステップ2を再実行する
- medium / low の指摘: 修正するか、対応しない理由を PR のコメントで返信する
- どの指摘にどのコミットで対応したかを PR のコメントで返信する
- 進行条件: high の指摘が0件、総合判定が「Ready for review 可」

### 5. PR 本文の更新と Ready for review

- エージェントが生成した「レビュー観点」「懸念点」を PR 本文に反映し、
  実装内容に合わせて調整する
- `gh pr ready <番号>` で Draft を解除する
- 進行条件: PR が Ready for review である

## 完了チェックリスト（全項目 yes で完了）

- [ ] 全レビューラウンドの指摘一覧が PR のレビューコメントとして投稿されている
- [ ] reviewer エージェントの総合判定が「Ready for review 可」である
- [ ] high 指摘が残っていない
- [ ] 対応しなかった指摘への理由が PR のコメントに記載されている
- [ ] PR 本文の「レビュー観点」「懸念点」が更新され、Draft が解除されている
