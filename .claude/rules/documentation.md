# ドキュメント記述規約

## MUST

1. **ennx リポジトリに存在しない資料への言及を一切記述しない**。ソースコード（docstring・コメント）はもちろん、`README.md`・`CLAUDE.md`・`.claude/rules/`・`.claude/skills/`・`docs/` を含むリポジトリ内のどのファイルにも書かない
2. **ドキュメントファイル名・GitHub イシュー番号（`#NN`）は、ソースコード（docstring・コメント）には記述しない**（本リポジトリ内の資源だが、番号・パスの変更のたびに参照が陳腐化するため）。詳細は CLAUDE.md「コーディング規約」
3. 設計判断の背景や要求の詳細を伝える必要がある場合、出典を示さずに要点を自己完結した説明としてリポジトリ内に転記する
4. 既存の記述がこの規約に反することに気づいた場合、単独で修正せずユーザーに報告する（ドキュメント編集は許可制。git-workflow.md「禁止事項」）

## 根拠

ADR 番号・UC 番号・ProductDocs への言及は、(1) 改廃・再採番のたびに陳腐化し、(2) ennxリポジトリ単体を参照する読者（このリポジトリしか見ていない開発者やエージェント）には実体を確認できない誤解を招く情報になる。2026-07 に、新規ルールファイル（architecture.md）作成時にADR 番号を書き込んでしまい、調査の結果 CLAUDE.md・README.md・docs/system-spec.md・複数のソースコードファイルにも同種の記述が既に残っていたことが判明し、リポジトリ全体を洗い出して削除した。本ルールはその再発防止のために明文化する。
